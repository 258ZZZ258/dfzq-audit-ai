1. **主干 S0–S3 整体建立在"我方拿到原始文件、自己解析并按条款结构切块"的假设上**(§1.7):预切块语料会跳过 S1、架空 S2 条款类指标(①②③⑦)、且无法用 S3 现有路径生成合法 `clause_path_norm`/`chunk_id`。**S0 白名单只认 docx/pdf/jpg/png,源系统导出现在连接入口都进不去**。

4. 给出三条候选路径(§3):**A =新增 P-PRESEG 适配 profile**、**B =独立直采通道**、**C =分型混合(结构化字段+链接直采,正文视原文件可得性仍走现管线)**。倾向性分析(**待讨论决策**):C 是红线零触碰的最低风险路径,但依赖"原文件可随导出获取"这一 P0 未知项;A 是正统长期路径,但有"profile 配置缝需先做实"的隐含前置工作;B 首期最快、长期工具链适配债最高。
5. 未决问题 18 项(P0×6 / P1×12,§4),**最高优先级是导出样例**——它一次性解决页码/粒度/主键/格式四个 P0。

## 3. 候选方案对比(只对比,不选择;倾向性分析标注"待讨论决策")

### 方向 A:新增摄取 profile(P-PRESEG 适配器)

源导出经**适配器转为与 S3 产物同构的 ChunkSpec 流**,从 S4 汇入现管线;现管线完整保留为兜底。

- **改动范围**:S0(白名单+新接入形态+manifest 扩展)、新增 `preseg_adapter`(源块→ChunkSpec:clause_path_norm 推导器+seq 分配+页码透传/置空)、profile_router 加分支、QC 启用子集(仿 P-CASE:④⑥+新完整率指标;若无页码禁④)、S4 起全复用(字典/版本链/META_REVIEW)、case 结构化字段直装 upsert_case。
- **隐含前置**:profile 配置缝做实(至少 QC 阈值/启用集进 profiles.yaml)+ QC 阈值 per-profile 化——B8 的"配置驱动"要求现状不满足。
- **工作量粗估**:中(推导器+适配器+profile 缝,≈3-5 人周;含 P-MISC 式降级设计复用)。
- **风险**:推导器质量决定 chunk_id 幂等与引用对齐(源标识不规范时错切→错引);源格式变化=改适配器。
- **B1-B8**:B1🟡(推导器)B3🔴(同全局)B7🟢 B8🟡(前置缝)。
- **可回退性**:好——profile 开关级,原路径无损保留。

### 方向 B:独立直采通道

源数据不走 S0–S5 状态机,独立 loader 直写 doc_versions/chunks/cases + Milvus,仅共享 PG/Milvus 写入层(pg_io/milvus_io/corpus_rows)。

- **改动范围**:新 loader 模块(读源导出→建 dv/chunks/cases→embed→upsert);绕过 orchestrator/状态机。
- **工作量粗估**:首期小(≈2-3 人周)。
- **风险(高,长尾)**:**双写路径漂移**——全部运维/验证工具假设状态机数据:reprocess/rebuild/reconcile/idempotency/T2/T4(eval/)对"无 pipeline_events、pipeline_status 语义缺失"的直采数据行为未定义;QC 整层缺失;B7 需自建批次挂接;后续每个新工具都要"两条路径都支持"。
- **B1-B8**:B1🟡 B3🔴 B7🟡(需补挂批次)B8🟡(与"接口缝替换"哲学相悖——它是旁路不是缝)。
- **可回退性**:中——按 batch_id 删可回滚数据,但代码是并行体系,弃用=沉没。

### 方向 C(补充):分型混合——"结构化字段+链接直采,正文择优"

按**数据形态**分流,而非按"源/自建"一刀切:
1. **案例结构化字段+违反法规子表 → 直采进 cases 表**(upsert_case 幂等现成):点亮桥接双通道、替代 case_l2 LLM 引用抽取——**收益最大、改动最小、最快兑现**;涉案人员入新表。
2. **内外规元数据(文号/日期/效力/位阶/业务类别/适用对象/关联文件)→ 自动生成 manifest**:源系统作"manifest 生成器",替代人工填 11 列+版本链人工录入(**两个节省点直接兑现**),文档本体仍走现管线。
3. **正文**:原文件/附件**可随导出获取**→仍走现 S1–S3 解析(**保四级页码引用,B3 零冲击**);不可获取→该部分语料退回方向 A 的预切块适配(或暂缓)。
- **工作量粗估**:第 1+2 步小(≈1-2 人周);第 3 步为 0(复用)或退化为 A。
- **风险**:**成立前提=原文件可导出(P0 §4-6)**;没吃到"免解析"的算力/时间红利(全量解析成本仍在);源预切块正文被闲置(若甲方期望"以平台切块为准"则不满足)。
- **B1-B8**:全绿或既有黄(B3 🟢——正文自己解析有页码)。
- **可回退性**:极好——纯增量,不动任何现路径。

| 维度 | A 适配 profile | B 独立直采 | C 分型混合 |
|---|---|---|---|

| 工作量 | 中(3-5 人周) | 首期小、长期高 | 小(1-2 人周)+条件项 |
| B3 页码 | 🔴 需降级/回填 | 🔴 同 | 🟢(正文自解析)|

**双通道并存的语料归属规则(三方向共通,待样例后定稿)**:监管问答——源系统**无此模块**(表头确认)→继续自建 P-QA 通道(需确认甲方是否另有来源,P0);案例结构化字段→源系统权威;内外规——取决于覆盖率(P0 §4-4)与原文件可得性,源覆盖内的走新通道、覆盖外(历史件/外部补充件)走现管线兜底;冲突仲裁——同一文档两通道都出现时以哪边为准,建议"源系统覆盖即源优先",待讨论。

**倾向性分析(待讨论决策)**:若导出样例证实"原文件可获取",**C 是首选起步路径**(红线零触碰、两大节省点立即兑现、B3 无冲击),且 C 与 A **不互斥**——C 先行,A 作为"源预切块正文"到位后的第二阶段,B **不建议**(工具链双轨债与 B8 哲学冲突)。若原文件不可获取,则 A 为主路径,B3 按降级三级+显式标识处置(需甲方对验收硬约束的let-down 确认)。
